# CarbonMint gauge reader

Reads the water level from drone photos of AWD (alternate wetting and drying) field gauges. Each gauge is a float
rod with red rings: the more rings show above the sleeve, the more water. One ring is 1 cm.

- **v0**: the company's current detector (`src/enhanced-detector.ts`). Rebuilt here in Python from its written
  description (`docs/v0-spec.md`), so both versions can be scored on the same photos.
- **v1**: our ring-rhythm reader, a trained confidence model, a bad-gauge check, and the company's own acceptance
  rule.
- **v2**: v1 plus two reader fixes (the ring gap can't lock onto a multiple of itself; rings are counted gap by gap
  because perspective stretches the gap) and the teammate's colour locator when ours finds no rod.

### What to keep in mind

- **Labels:**
  - The ring counts were read by eye, then checked by a person on two random samples of 15.
  - Round 1 matched 10/15, so the labels were fixed and moved to whole rings.
  - Round 2 matched 15/15.
- **v0 is rebuilt, not the original.**
  - Four numbers the description leaves open are marked `ASSUMED` in `gauge/v0.py`.
  - The company reports about 50% on its own photos. On these photos v0 scores lower, mainly because its brightness
    floor (value 50% or more) drops shaded rings. Relaxing that one rule lifts it to 55/127 (`scripts/v0_diag.py`).
  - The TypeScript source would settle this.
- **v1's confidence is trained leave-one-plot-out.**
  - Each field is scored by a model that never saw it.
  - The reader's hand-written rules were designed on these same photos, so the next batch of field photos is the
    real test.
- **v2 trade-off:** 5 more photos accepted and exact, but 16 accepted-and-wrong against v1's 13. Upscaling far rods,
  adding a ring at the sleeve, and using the teammate's count or score as confidence signals were tried and dropped:
  no gain, or more errors.
- **Open checks:**
  - The bad-gauge check falsely flags 1 of the 127 good gauges. It has never seen a real bad gauge.
  - "1 ring = 1 cm" comes from v0's description and still needs the company's confirmation.

## How v1 reads a photo

1. **Find the rod** by its stack of separate red rings on one near-upright line. A rod split by a leaf is joined
   back up. A plain grey rod with no paint showing reads 0 rings (dry), not "not found".
2. **Straighten it.** A curve through the ring centres follows the rod's lean and bend.
3. **Read the ring rhythm.** The pitch comes from the autocorrelation of the redness down the rod. The count is
   (last ring − first ring) ÷ pitch + 1, so rings hidden by leaves still count. Faint bands at the ends (sleeve rims,
   stains) are dropped.
4. **Confidence.** A logistic model (`gauge/v1.py`, weights in `models/v1_confidence.json`) estimates P(count is
   exact) from the reader's own signals and whether the visit's other shot agrees.
5. **Company rules.**
   - A photo is accepted at 0.7 or more.
   - A visit takes the mean of its accepted photos.
   - Level = count − 10.
   - Soil state: Flooded / Saturated / Drying / Irrigate now.
   - A reading that breaks the gauge's physics is never accepted and is noted "bad gauge".

## Layout

| `gauge/detect.py`, `gauge/measure.py` | Rod finder and ring reader |
| `gauge/v0.py` | v0 rebuilt from `docs/v0-spec.md` |

| `tests/` | `test_gauge.py` (reader, v0, v1), `test_app.py` (auth, roles, routes) |

## Run it

```bash
pip install -r requirements.txt opencv-python-headless   # OpenCV only for the teammate method
python -m unittest tests/test_gauge.py tests/test_app.py  # 29 tests

# with the original photos in "way points/":
python -m gauge.index "way points"   # data/index.csv (holds GPS: gitignored)
python -m gauge.run                  # v2 reader on every photo -> data/photo_reads_v2.csv
                                     # (data/photo_reads.csv is the frozen v1 run)
python scripts/run_v0.py             # v0
python scripts/run_teammate.py       # teammate method (needs OpenCV)
python scripts/compare.py            # the table above
python scripts/build_gallery.py && python scripts/build_site.py

python -m gauge.web 6900             # demo on http://127.0.0.1:6900
```

The demo will not start without `CM_ADMIN_PIN` and `CM_USER_PIN` (6+ characters each, see `.env.example`); there
are no default PINs. The local lane keeps its signing key in
`data/.secret`, which is gitignored.

## Data

The original drone photos are not in this repo. They carry the fields' GPS in their metadata. The demo uses
1200 px copies with every metadata block removed, and serves them only to a signed-in user.
